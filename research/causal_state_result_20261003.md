# 从不完整观测得到任务证据有效期：动态序列、动作预算与失败边界

这批实验建立了可以运行、复核的算法链路，并找到了一个具体的过度保守来源：**把本来不足以完成动作的证据误差也纳入校准，会缩短其他可用证据的有效期。** 先按动作预算筛选、再校准任务有效期，在同一组开发数据中把20Mbps紧凑消息的可用查询从预测管的3807提高到5154，但留下1次实际观测到的占用冲突。不能把这次提升写成已经解决安全或MobiCom创新。独立全新种子的有限验证另见`prospective_expiry_20261003`；其结果不在本报告数字中。

## 问题必须同时定义可信度与保守性

输入是当前不完整XYZ点云，输出是有来源时间、任务坐标、风险范围的最后有效时刻。不能只优化感知mAP或给消息固定TTL。源时刻为`t_s`，预测安全年龄为`L`，接收时刻为`t_r`，则动作资格为

```
绝对截止时刻 d = t_s + L
可用 ⇔ 已收到并完成验证，且 d ≥ now + 220ms
```

220ms由20ms时钟余量和200ms动作预算组成；20ms传播、采样处理、编码、串行传输、接收处理及各自FIFO排队另外付费。接收消息不会把来源时间变成当前时间；没有输出的扫描不会延长旧证据。

可信度用**整条序列内任意有效证据失败的概率**定义，视角、时间和查询之间可以相关。保守性另用对真实未来网格首次接触时刻的差距、可用查询及付费后的结果衡量。概率可信不能推出小时间差距。若两个物理状态产生同一观测，却有不同的真实安全期限`G1<G2`，任何仅依赖该观测、对两者都确定安全的算法必须输出`L≤G1`；在第二个状态上至少损失`G2-G1`。因此，无条件要求零错误与任意小保守性，需要额外可辨识性或运动/场景契约，不能由“语义”二字保证。

## 完整有限实验及数据范围

Sheng通过Windows已安装CARLA0.9.15完成冻结的930条计划：六个已知类别，各95条校准、60条测试。位置、朝向与目标速度由冻结随机种子独立抽取。物理车辆每tick设置目标速度，行人使用WalkerControl；无物理冻结。两个RSU同时扫描，0/5/10步各保留两帧，0..20步保留真实运动快照，步长50ms。867条成功采集，63次生成失败不补样；共5202帧、114818544个保存返回点。传感器报告459263772个原始返回，**只有每四点保存一点的样本可复核**。

360条计划测试中335条成功，25次失败保留在分母。2010个测试扫描中1998个输出候选；12个没有候选的扫描拒绝。每条计划测试有16个时刻、两个查询，共32个相关结果，即每方法每链路11520个计划查询。生成失败仍记为无授权查询，而不是从风险与效用分母移除。

XYZ组件前端完全继承既有冻结实现；语义ID只用于离线标签和事后审计。每个当前扫描独立保留所有候选中心，不等待另一视角或未来帧。实验已知单个目标类别、尺寸、对象数量、道路与传感器位置；这些不是由前端成功推断出的完整交通场景。

## 四种有效期策略与强比较

状态集合方案用95条校准序列的最大中心误差，加向外舍入与8mm量化保护；然后用已声明的`5t+1.5t²`运动包络求最早可能接触。预测管方案直接校准当前候选到未来11个50ms网格位置的残差，以`q+3t`膨胀；3m/s是预测器设计值，不是未经验证的真实速度上界。两者在测试上分别有3条中心/未来网格覆盖失败，半径恰好相同。

任务方案对当前量化候选计算固定8mm基础空间保护下的3m/s预测接触年龄`H`。离线标签`G`为当前至未来500ms网格上首次占用前1µs；无接触则为500ms，当前已占用则为−1µs。校准序列分数为所有当前来源/视角/任务对的`max(0,H-G)`的最大值，类别修正量`δ`取95条序列最大值，输出`L=max(-1,H-δ)`。未来真实状态不进入接收器。

未筛选任务方案的总效用低于预测管。动作资格修正版只对`H≥220ms`的任务对校准误差，其余明确不给授权。这个阈值继承现有动作预算，没有按测试调参。它删除了即使修正量为零也不可能支持动作的证据对，避免这些误差压缩其他期限。理论上同一校准数据的修正量只会下降；付费效用仍须实测。

所有策略都比较三个真实表示：152B中位数的量化中心并集、179B中位数的无损float64中心、约191946B中位数的完整**保存XYZ**。三个表示重建同一中心与相同任务政策，分别付自己的处理和传输费用。强无损中心基线可以打平或略胜紧凑消息。固定200ms方案总是短于220ms预算，只有诊断作用，不能拿它当主要胜利基线。策略配置和校准注册表已在收发两端离线共享，未计首次分发成本。

| 策略 | 并集20Mbps | 无损中心20Mbps | 完整保存XYZ20Mbps | 并集2Mbps | 20Mbps并集占用冲突 |
|---|---:|---:|---:|---:|---:|
| 状态集合+运动包络 | 3080 | 3084 | 1150 | 3068 | 0 |
| 未来网格预测管 | 3807 | 3801 | 1685 | 3794 | 0 |
| 未筛选任务修正 | 2770 | 2775 | 961 | 2758 | 0 |
| 动作资格后任务修正 | 5154 | 5154 | 2298 | 5138 | **1** |

所有分母均为11520；这些是相关的计划查询，不能当11520个独立安全样本。完整XYZ在2Mbps均无可用查询。动作修正版的并集与无损中心在20Mbps完全打平，说明当前主要改善来自校准对象和动作资格，而不是新的压缩算法。其并集中位来源处理2094.5µs、接收处理308.5µs；记录的是三次实测最大值，不是WCET。传播与队列另计。

## 校准可信度与保守性必须分开报告

固定前端、评分与资格规则若在新校准数据之前冻结，且类别内完整序列iid，95个校准分数的最大值满足

```
P_calibration[P_new(序列分数 > 最大校准分数) > 5%] ≤ 0.95^95
六类联合校准置信下界 ≥ 1 − 6×0.95^95 = 95.4091%
```

这是标准最大次序统计量的容忍界。它不是新的conformal定理，也不是部署中任意连续时刻、给定授权条件下错误率≤5%的保证。主状态与预测管在采集前冻结；任务方案和动作方案在看过主结果后提出，**本批任务方案数字只属于复用数据的开发比较**。上述理论不能补回独立校准与前瞻验证；因此冻结了另一个全新批次。

开发数据风险界具有事后方案选择限制；这里保留数值，不作为新方案正式安全证书。Sprinter的8.36m半径只给主状态方案2个、预测管11个可用查询，而动作方案给645个。这个改善伴随着真实失败，不能忽略。

动作方案对真实未来网格期限的正保守差距，在有至少220ms几何资格的来源任务对上，各类中位数为0或1.461ms；但全体可观测来源任务对的类别均值仍为43.46–52.49ms，最大达到500.001ms，Sprinter还高估339.113ms。500ms截断使无未来接触的很多样本差距为零，**零中位数不能解释为无截断、完整原始观测下的近最优有效期**。同样付费到达、同样基础动作筛选的完美未来网格标签oracle给并集5519个查询，算法5154个；oracle只用于诊断，不能实施，也不能抵消1次错误授权。

## 一个保留的具体反例

`vehicle_mercedes_sprinter_test_041`在step10的view0漏掉了当前左侧查询区域的占用，预测340.573ms基础有效期，减1.461ms后为339.112ms。step12已收到并完成验证，剩239.112ms，超过220ms而授权，但实际保存的车体圆盘快照仍占用该区域。另一视角在相同来源时刻的基础有效期为零；“保留已送达最长截止时刻”的规则没有否决坏视角。完整来源、期限、消息与查询记录保存在`action_counterexample.json`。

这不是数值求根失败，而是不完整观测、组件漏检与选择规则之间的统计失配。新批次严格沿用冻结规则，不用这条测试反例调参或删样。若前瞻结果仍失败，必须报告；任何额外否决/补充证据策略应作为新算法重新冻结与验证。

## 审计、物理限制与新颖性

本地与sheng九组独立审计/汇总输出逐字节一致，两个主机各7项因果测试通过。原始审计独立栅格组件重建，核对全部保存点、消息、校准统计、绝对来源年龄与三段FIFO。每个策略核对15606个表示消息引用和10404个几何/期限边界。预测管审计另检查56969个来源—未来配对。主运动审计在26010个快照位移检查中未违反声明包络；这没有覆盖tick之间的运动。

车体包围角点有12869个快照超出按尺寸舍入的半径，最大4.112863µm，作为实际浮点/模型差距保留。独立核对所有保存的真实目标返回点，没有发现XY或3D半径外返回；7帧没有目标返回。此检查不覆盖未返回或未保存的表面，不证明整个物理模型。SHA保证内容完整性而不是身份认证。CARLA模拟时间与实测墙钟耗时组合成离散事件模型，没有真实无线链路、ego驾驶或连续碰撞安全验证。

文献已经覆盖安全分数校准和完整选择流程的校准：[Luo等ICRA2022](https://stanfordasl.github.io/wp-content/papercite-data/pdf/Luo.Zhao.ICRA22.pdf)明确包含TTC；[Conformal Risk Control, ICLR2024](https://arxiv.org/html/2208.02814)控制单调损失；[Chang与Ahmed的2026预印本](https://arxiv.org/html/2608.26533)直接校准选定轨迹的安全裕度，并把资格、选择与session最大值纳入固定流程。[Lindemann等RA-L2023](https://arxiv.org/html/2210.10254)已连接校准未来区域与安全规划。这些思路不能当本项目的新方法。Where2comm与CoBEVFlow分别提供通信内容/请求与异步对齐背景，也不能以名称代替实现基线。详细阅读边界见`READING.md`。

MobiCom候选问题现应聚焦：**在动作与付费到达预算下，哪条不完整证据值得校准、传输或补充，以及剩余有效期何时足以支持动作。** 当前结果支持动作资格对校准保守性的实质影响，但尚未建立新的在线证据选择算法、真实链路/闭环收益、完整场景风险或MobiCom新颖性。项目完整目标仍未完成。
