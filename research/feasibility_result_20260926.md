**sheng 初步实验结论：机制成立，实际数据收益尚未成立**

后续更新：正式的语义通信机制、鲁棒性和 CARLA 闭环有限实验已经完成，见[完整实验结果](full_experiment_result_20260926.md)。新结果没有推翻本报告的负结论：集合效用本身仍未优于强覆盖方法；它把可行方向收窄为耦合链路下的联合到达感知调度。

日期：2026-09-26。实验已经在 sheng 执行完毕。当前结论是：**证据互补可以产生单步选择无法捕获的收益，但这版 OPV2V 开环实现没有通过“优于强单步基线”的立项门槛。暂不建议直接投入大规模训练。**

这并不证明原假设不可能成立。更准确的解释是：本次生成模型支持机制；现成数据与静态探针很少提供协作影响动作的机会，尚未构成合格的驾驶收益验证。

**实验一：发送前不知道消息结果，组合收益是否仍然存在？**

模型包含四个潜在冲突区域、带误报/漏报的二元观测、若干具有单项或多项前提的动作及保守停止动作。选择器只知道先验、观测模型和动作规则，不知道潜在真实状态，也不知道未接收的观测结果。对全部状态、观测和丢包结果精确求期望。

效用定义为进展奖励减去 20 倍冲突事件代价，并使用声明模型下的后验风险阈值。它是明确规定的合成效用，不是碰撞率、驾驶分数或准确率。

在每条消息到达概率 0.8 时：

| 结构与预算 | 集合最优相对强单步 VoI 的平均效用差 | 按随机种子 bootstrap 的 95% 区间 | 解释 |
|---|---:|---:|---|
| 动作只需单处证据；预算 2 条 | 约 0 | 约 [0, 0] | 对照中没有无条件的组合优势 |
| 动作需要两处证据；预算 2 条 | +0.0830 | [0.0706, 0.0972] | 200 个实例中 140 个存在正收益 |
| 动作需要三处证据；预算 3 条 | +0.0567 | [0.0488, 0.0652] | 更高阶的互补也可能存在 |

二步前瞻在两条预算的情形可以达到该小问题的集合最优；由于这时枚举二元组合就覆盖了全部预算可行组合，这不是独立的算法创新证据。在三前提、三条预算时，二步前瞻平均改善为 +0.0277，小于集合最优的 +0.0567，说明限制到低阶交互仍会留下损失。

这些结果支持“可能存在互补价值”，但结构由生成器指定，不证明自然路况的发生率，更不能当作 MobiCom 创新已经成立。此实验也未包含真实控制报文成本。

**实验二：冻结感知输出上，组合选择比强单项方法好多少？**

本轮使用已有缓存中全部 ego/neighbor 检测框及置信度，而非仅使用 GT 匹配对象表。记录路线来自对应原始 YAML；索引顺序与原 OpenCOOD 读取逻辑核对过。

两种探针分别为：沿原记录路线选择不同前进距离/停止；在此基础上增加左右侧向候选。后者未核实车道合法性和车辆动力学，只能作为压力测试。评价用静态车体扫掠区域与物体框的相交关系；它不是动态规划器，也不是碰撞概率。

发送端最多选八个邻车检测对象。每条对象消息实际序列化为 32 字节，并进行量化解码和 CRC 检查。接收端显式发送量化路线及本地动作阻挡摘要，所以发送端使用的接收状态不是免费信息。选择器不接触 GT；GT 仅用于选择后的独立几何诊断。

比较方法包括：无通信、无需任务请求的置信度对象广播、覆盖度排序、强单步 VoI、二步前瞻、小规模集合最优。它们是本试验中的透明算法对照，不是 AutoCast、Select2Drive 等官方方法的完整复现。

| 检查项 | 修正后的实际结果 |
|---|---|
| 集合最优相对强单步 VoI 的参考决策损失改善 | 两种探针、全部 13 个配置中，230 帧评估的逐帧期望差均为 0 |
| 153 帧开发数据中的同类优势 | 同样没有观察到 |
| 加入全部候选邻车信息会改变动作的评估帧 | 每种探针均仅 2/230 帧，约 0.87%；两帧来自同一场景 |
| 宽松 512 字节、可靠传输 | 简单对象广播也能达到全候选参考决策 |
| 160 字节、到达概率 0.8、侧向压力探针 | 组合/单步方法参考损失 0.3120；无任务请求的对象广播为 0.1733，后者更低 |
| 原路线/侧向探针公共构造耗时 P95 | 约 7.32 ms / 10.15 ms；不含原始感知网络推理 |

这里的损失以人为固定的静态阻挡代价为单位，**不能把 0.3120 等数值解释为碰撞概率**。侧向探针中的简单广播优势说明，在这个单发送者模型中，请求的开销和丢失可以抵消任务选择的价值；它不是对所有 V2X 协作架构的结论。

场景 bootstrap 对“组合减单步”的区间也为 [0,0]，原因是本样本每个配对差都是零。这不代表总体效应确定为零。有效事件只有两帧，且来自一个场景，因此不能用大量配置行数制造统计把握。

集合方法有时发送更少的对象，但本轮单步基线会填满可用预算；给单步方法增加简单的冗余删除或停止规则，就可能减少这部分差距。因此不把这些字节差包装成组合推理的创新收益。

**重要的审计修正**

初次完整数据实验产生异常高的静态阻挡比例。检查发现：邻车能检测到接收车自身，合并标注也包含接收车；这些对象在 ego 坐标中接近原点。将感知缓存用于运动决策时，必须处理这种自车对象，否则会出现“邻车通知本车自己挡住自己”的虚假增益。

修正版本对预测和标注分别使用同一个、只依赖已知自车位置的规则：对象中心距原点小于 1.5m，且框覆盖原点时进行自车抑制，不进行 GT 关联。评估帧累计删除 184 个邻车自车预测和 187 个标注自车框。近距离异常重叠仍是该启发式的边界。

修正前 `results/opv2v` 的结果保留在服务器，仅供审计；最终结论只依据 `results/opv2v_self_filtered`。另一个修正是为空规划轨迹建立显式排除清单，没有用人工路线替代。

八项测试通过，覆盖概率积分、消息/请求字节与 CRC、互补反例、几何阻挡、自车过滤及空路线处理。结果预算、概率范围、配对行数和损失边界检查通过。本地脚本 SHA-256 与服务器运行 manifest 一致。

**这次对 idea 的判断应怎样更新？**

1. **机制可行：支持。** 不知道消息具体结果时，仍可因任务前提互补而受益于非短视选择。
2. **当前对象通信实现具有实际数据优势：不支持。** 强单步方法已达到小规模集合最优，没有测到算法余量。
3. **真实驾驶问题存在足够频繁的这种结构：未验证。** 现有缓存中动作差异太少；静态对象框也没有表达“已观察为空闲”和“尚未观察”的区别。
4. **可以直接立项并大规模训练：目前不建议。** 不能把合成实例的正结果代替应用收益证据。

值得继续的小范围实验，应增加三个真实可检验条件：至少两个独立视角；对未知区域与观测空闲的明确区分；闭环中的双向遮挡和同等安全水平下的通行效率。还应保留单危险源、无协作价值和无带宽瓶颈对照。若这些条件下组合上界仍贴近单步方法，就放弃“组合选择”为核心贡献；若只有新表示有效，就必须把贡献重新定位为证据表示，而不能归功于调度算法。
