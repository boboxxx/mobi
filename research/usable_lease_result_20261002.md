# 选择有效期的完整成本：576 次对照得到的负结果

本轮在 sheng 完成两批各 288 次有限对照。**简单删减冗余射线，以及反复生成多个有效期再事后择优，均未解决到达后的可用有效期。** 完整数据在 `results/usable_lease_20261002`，冻结协议和源代码在 `experiments/usable_lease_20261002`。这是已有观测的配对重放，不是新增驾驶实验。

## 问题与保持的可信条件

证据的几何有效期 H 不等于接收端还有 H 可用：采集、源生成、接收验证和按字节传输都消耗同一个截止时间。本轮计算

    可用时间 = 已发送 H − 采集 − 生成 − 接收验证 − 建模传输。

传输为 20 ms + 字节量×8/20 Mbps。另把总年龄向上取整到 50 ms 物理步，要求余下时长严格大于既有的 200 ms 动作包络时长。此项仅为反事实计时准入，不代表已经证明动作可实现、物理安全或未来运行时上界。

所有方法保持原传感器、射线年龄/误差、障碍半径/运动上界和父证据限制。未覆盖单元继续未知。新删除法只在每个受其覆盖的单元都有其他射线支持时删除该射线；最终是候选集内的包含极小覆盖，不是全局最小字节覆盖。接收端仍读取原始整数射线并完整重算全部证明。

六个输入来自上一轮明确标为事后选取的六个状态，包括两个根、两个续期、稀疏视角和历史已经丢失的负对照。四个正常输入的全量观测边界均为 480.303 ms；稀疏视角为 60.008 ms，丢失历史的自遮挡输入为零。测试发送时长 200/400/450/475 ms，各三次重复，每次随机排列方法执行顺序。这些是受控重复，不是独立场景样本，不能建立分布置信区间或 WCET。

## 结果

第一批比较最近单元支持、原有贪心覆盖、原有修复/贪心回退和新删除法。最近支持产生过多射线，全部触及包上限而拒绝；其余方法产生 144 次非空证明。删除法例如在首个根、400 ms 目标上生成约 0.9 s，消息还略大于贪心，未形成有效收益。

为消除 Python 实现开销的混淆，第二批同时为贪心和删除法使用向量化覆盖图与 C++ 内核，仍保留原有贪心和快速修复对照。编译耗时约 356 ms，加载耗时单独归档；编译/加载在每消息计时之外。公共不变网格由前置边界诊断预热，不能称为整个进程的冷启动。

| 输入/发送目标 | 原贪心生成中位数 | 原修复生成中位数 | 编译贪心生成中位数 | 编译删除生成中位数 |
|---|---:|---:|---:|---:|
| 首个根 / 400 ms | 624.24 ms | 638.68 ms | 429.80 ms | 465.11 ms |
| 第二个根 / 400 ms | 629.10 ms | 49.78 ms | 438.46 ms | 469.28 ms |
| 第一次续期 / 400 ms | 520.06 ms | 45.44 ms | 363.71 ms | 379.72 ms |
| 第二次续期 / 400 ms | 529.01 ms | 83.68 ms | 372.35 ms | 389.98 ms |
| 第二次续期 / 475 ms | 607.38 ms | 675.42 ms | 425.57 ms | 451.87 ms |

第二次续期的 400 ms 原贪心/编译贪心消息同为 67,730 字节，删除法为 68,906 字节，快速修复为 77,443 字节。编译贪心改善重建成本，但仍明显慢于正常情况下的局部修复。扩展到 475 ms 后旧修复模板超出其修补能力，发生全量回退；编译后的全量法也没解决截止时间。

两批分别产生 144/192 次非空证明。**576 次计时动作准入全部失败。** 例如第二个根的 400 ms 快速修复在到达后还有约 225.24 ms，但向上取整后的年龄为 200 ms；加 200 ms 动作时长恰好到期，严格规则必须拒绝。这种拒绝不能用浮点容差消除。

事后只给最优候选计费会遗漏搜索成本。独立审计另外对每个状态/方法/重复把四个目标的所有生成和检查成本计入，再只发送所选候选；所有这种付费菜单的动作准入也都失败。该菜单是建模顺序计算诊断，并未作为分布式在线控制器部署。不能把事后最优时长当作免费算法收益。

## 审计与研究方向

112 份首重复保存消息全部通过独立完整几何、原始射线来源和完整域最大边界重算；64 份第二批消息与对应第一批参考逐字节相同。八项不同单元测试通过，其中包括 100 个随机覆盖集合的两种原生选择器等价对照及非法 CSR 输入拒绝。第一次独立审计因缺少模块搜索路径在读数据前失败；只修复审计导入并保留失败记录，两批基准未修改或重跑。本地重放又发现旧服务器目录的 AppleDouble `._*.py` 被原依赖文件匹配规则列入清单；已保留原清单和这些元数据字节，归入独立 `archived_metadata`，与可执行源码分开核验，没有改写原始消息或计时。没有启动新的 CARLA 进程或持续研究循环。

这个负结果改变后续算法目标：应保持已经证实的内部覆盖，只对更长有效期新增的未知单元寻找**误差已验证**的补充射线，避免每次重建整张覆盖图。旧修复器按名义距离一次加入 4/16 个邻居，会发送较多未必必要的射线；下一步须与其做同输入、同目标时长、同字节链路和完整接收验证的匹配对照。任何新方法都需要计入生成成本，而非仅报告 H 或压缩率。

[本轮正文文献核查](usable_lease_reading_20261002.md)也明确：空间稀疏语义通信、AoI/VoI 与任务相关性均已有工作。当前覆盖删除/编译加速不能单独声称 MobiCom 新颖性。传感器和障碍核心物理合同、到期后的合法恢复、有运动闭环/备份、真实链路和独立场景泛化仍未完成；本轮是可复现进展，不是完整项目完成。
