# IEEE Transactions 方向：文献阅读与实验重构

日期：2026-10-11。按 PaperLocus 的方法论文流程整理；区分作者主张、已读证据与本项目推断。目标由 MobiCom 改为 IEEE Transactions。暂以 **TVT 为算法主线的候选期刊**，TMC 为移动计算/网络系统贡献充分时的候选；这是选题判断，不是投稿成熟度或接收承诺。原已冻结实验不改写。

## 逐篇阅读记录

### 1. SComCP：任务语义压缩的强近邻

[作者全文 v1](https://arxiv.org/html/2507.00895v1)，[TVT 发表记录](https://ieeexplore.ieee.org/abstract/document/11355867/)，DOI 10.1109/TVT.2026.3654968。阅读 §II–IV 的问题、模块、训练与实验，未复现网络。

在 PointPillars 和注意力融合上改动特征选择与 JSCC，以检测 AP 衡量任务质量。OPV2V 有固定训练/验证/测试划分；比较沿用相同骨干，传统量化＋LDPC方案与语义方案按信道使用次数配平；训练 Rayleigh，测试 AWGN/Rayleigh，另有模块消融。**可借鉴：成本配平、训练/测试信道分离、分模块消融。**本文展示检测/通信折中，不能从 AP 曲线推出接收端某段驾驶动作安全。我们也不能仅换成“安全语义”便宣称创新。

### 2. TCOM：部分可观测采样与传输已经被正式建模

[作者全文 v3](https://arxiv.org/html/2311.06522v3)，[TCOM 发表记录](https://ieeexplore.ieee.org/document/10778564/)，DOI 10.1109/TCOMM.2024.3511935，2025年卷期。阅读 §III–V、Proposition 1 与相关证明思路；机构 PDF 返回403，改读作者稿，未逐项核对最终排版版。

Zakeri 等把采样耗能导致的不可观测状态转成 belief MDP，分别优化失真和 AoII。有限化后的模型用相对价值迭代，一般 AoII 分支用 DQN。对比 AoI 优化、机会采样与相应语义目标，扫转移、能量、信道、采样成本，并检查截断尺度影响。**可借鉴：先说明充分统计量，再解决优化；把“优化了什么”与“评价了什么”分开。**平均 AoII 不是整个动作窗口的碰撞风险，也不构成逐观测风险保证。

### 3. KTH 遮挡行人：不能再把集合融合当原创

[机构全文](https://people.kth.se/~kallej/papers/Situational_CTR2025_Narri.pdf)，[出版记录](https://doi.org/10.1016/j.commtr.2025.100190)。阅读 §2–7、Algorithm 1；PDF 双栏另作列提取以核对。方法属于算法＋实验叙事，未复现实车。

Narri 等把运动传播后的约束 zonotope 与观测集求交，再融合各单元。保证以初始/测量/运动集合可信、一致等假设为条件；§4.2.2 明确未处理融合为空的情况。仿真用“有/无行人 × 有/无 V2X”四格区分必要停车和遮挡造成的停车。实车报告处理约200ms，扩张测量不确定性；ITS-G5 约100B、10Hz，平均链路延迟约20ms，未补偿通信延迟。**可借鉴：不要只测有危险场景；必须测没有危险时是否过度停车。**本项目已知静止目标的小进展测试远不足以替代这个设计。

### 4. 多传感器部分状态与时延：不能把历史 belief 当原创

[When and Which Sensor to Observe，作者 v1](https://arxiv.org/html/2606.30623v1)。2026年预印本，未把它记作 Transactions 已发表论文。阅读 §III–VI 与主文限制，未复现 RL。

Cosandal 等维护联合状态与 AoII 的 belief，通过 MPC/学习终端代价选择何时请求哪个传感器。假定已知联合 Markov 转移、固定一槽前向传输、瞬时反向请求。实验含二维位置部分观测与相关事件；比较随机、轮询及擦除感知轮询，扫成本/信道/搜索深度，记录计算代价。**可借鉴：多源非独立性、丢包感知基线、策略复杂度。**我们的物理目标几何、未知观测模型及完整动作事件不能直接由其已知 Markov 假设解决。

### 5. CP-SIPP：安全区间与置信度调整已有先例

[作者 v1](https://arxiv.org/html/2511.18170v1)，[项目页](https://time-aware-planning.github.io/)。阅读 §2–4 的误差、区间、路径风险和仿真；v2 URL 返回404，未据此推断存在 v2，也未自行认证作者的全部保证。

方法将预测误差与置信等级引入 SIPP，另有 ACP-RRT。主文路径风险命题明确以各时点边缘覆盖成立为条件，用 union bound 合并。§4 主要给导航/置信度轨迹与无 ACP 对照。**可借鉴：逐点安全与整条轨迹安全要分别写；长时间范围要付出风险预算。**本项目不能把固定校准样本的经验比例当作某个自适应选中动作的真实安全概率；未拒绝分布变化也不证明交换性。

### 6. StochSIPP：最接近“可信而不过度保守”的规划参照

[作者 v1](https://arxiv.org/html/2608.00792v1)。2026年预印本。阅读主文建模、证明范围、实验及补充的范围/实验说明；未完整复算复杂度证明或复现全部代码。

安全区间状态在回合初抽取，局部精确观测后才能使用不确定边；AND/OR 搜索得到条件策略。最优性依赖独立固定区间变量，安全性依赖可靠安全标签、精确观测和计划时序。实验单独承认由整条轨迹抽样产生相关性，因而该分布不受其独立模型最优性定理覆盖。**可借鉴：配对世界、任务成功与到达时间同时报告、扩大并发模糊变量看复杂度爆炸。**不能把未到达的停车策略计作任务成功，也不能拿危险策略较短时间作为优势。

[FullPerception，TMC](https://ieeexplore.ieee.org/document/11129936/)，DOI 10.1109/TMC.2025.3600060：仅出版摘要/元数据，确认其网络盲区调度、资源分配与近似算法定位，**未读完整方法、未复现**。CARA 的先前全文阅读记录见 [已有控制文献笔记](expiry_control_prior_work_20261004.md)；概率自触发车队控制的 TVT DOI 10.1109/TVT.2023.3288210 本轮仅检索摘要，不能据此评价全部理论。基础 [SIPP 原文](https://www.cs.cmu.edu/~maxim/files/sipp_icra11.pdf) 的安全区间定义也已是先例。

## 本项目的故事应怎样改

1. **问题是证据能否支持实际动作。** 不完整回波可能兼容不同状态、运动意图和观测误差；即使报文年轻，整个动作期间仍可能冲突。另一方面，一个统一最坏运动球可能把大量安全动作拒绝。
2. **决定可信度的瓶颈是观测与动力学模型的有效性。** 只把位置集合变成 deadline，或把预测置信度变成一个数字，都不能跳过这一步。当前固定目标实验已证明有限条件下的可用性，尚未证明充分解决这项瓶颈。
3. **候选算法输出源时刻锚定的动作风险包络。** 接收方支付完整使用时间，只接受动作窗口的联合风险上界满足预算的请求。先用可精确求解的参考模型拆开终点检查、union bound、模型失配与期限表示；区间/bitmap都作为已有编码方法。
4. **核心贡献仍需建立。** 候选方向是从不完整传感器观测建立紧而覆盖有效的时序假设集，并证明其在接收策略选用后仍可信；压缩与及时使用是辅助环节。不能把 Bayes、Markov首达概率、SIPP、conformal 或 LTT 组合直接报成原创定理。

## 从文献移植的实验要求

| 要回答的问题 | 具体设计 | 避免的混淆 |
|---|---|---|
| 不完整观测导致多大额外保守性？ | 同场景、同回波，扫描遮挡程度与观测历史；报告假设集合漏覆和 oracle 有效期差 | 真值不能进入运行时 |
| 较少停车是否以风险为代价？ | 行人存在/不存在、跨越/远离/停留；报告路线完成、冲突、必要与不必要拒绝 | 拒绝不是任务成功 |
| 动作窗口比终点检查可靠多少？ | 固定动作、同模型/时间，检查整个包络及终点消融 | 不能只看最终安全状态 |
| 紧集合是否真正带来长有效期？ | 粗最坏可达集、集合观察器、时序预测集、精确有限模型参照 | 不同假设不能直接归因于算法 |
| 通信表示是否有优势？ | 完整包络、bitmap、紧凑cone、静态deadline，同码率/字节/处理预算 | 原批次cone已有负证据，必须保留 |
| 实际延迟后还可用吗？ | 相同源频率，收费的传感处理、源计算、传输、接收、控制动作与制动 | 源频率加倍不是免费改进 |
| 数据量与统计可靠性够吗？ | 独立回合拆分开发/认证/测试；整回合风险与成功，配对差异、精确区间 | 帧/查询不能当独立样本 |
| 假设失配会怎样？ | 未登记遮挡目标、突然转向、传感失检、负载/丢包变化，明确拒绝域 | 不拿已知目标证书推广未知物体 |

这些是拟执行要求。尚未完成的动态驾驶、实际传输、模型校准和外部分布测试，不能写成结果。新的有限验证见 [预注册协议](../experiments/action_window_reference_20261011/PROTOCOL.md)。它只检查机制；不会把玩具模型当作期刊级验证。
