# 不完整观测的证据有效期：新闭环失败、最大边界与严格时钟

本轮在 sheng 完成八组新的有限 CARLA 运行、完整源数据重放以及有效期边界诊断。结论是：**固定的 400 ms 并不等于从观测得到的最长证据有效期；但是，仅消除这部分保守性仍不足以让当前系统执行动作。** 原始数据和代码见 `results/live_repair_closed_loop_20261001`、`experiments/live_repair_20261001` 与 `experiments/expiry_frontier_20261001`。

## 回答核心问题

采用“与观测相容的未知空间”而不是未检出目标的置信度：保留每个当前射线和合法历史尚未排除的网格单元，传播障碍的有界运动，求其最早进入指定区域的时间。新算法一次建立排除集合，然后二分整数微秒，得到**现有固定区域网格证书中的最大有效期**。每个输出附有限制类别和最近未排除单元，接收端可以复核。

它消除了固定时长或粗时间网格带来的额外保守性；没有消除网格、障碍形状和运动上界的保守性。可靠性仍以传感误差、不透明核心、运动上界和历史有效性成立为条件。没有这些前提，同一份不完整观测可以对应“空道路”和“遮挡目标即将侵入”，不能无条件承诺正有效期。完整定义、等价推导和限制见 [THEORY.md](../experiments/expiry_frontier_20261001/THEORY.md)。

有效期必须与实际到达及完整动作共用时钟：`向上取整的到达时间 + 动作/有限备份时长 < 整数到期点`，同时整段动作占据必须包含在已验证区域中。传输、计算、等待和丢包不能重置证据年龄。观察到的平均计算时间也不能冒充最坏时延保证。

## 八组新闭环运行

两个既有 RSU 视角，各比较原快速续期与局部修复，两次顺序平衡重复；不是八个独立道路场景。保持相同 400 ms 几何时长、20 ms 固定链路模型、原始射线契约、完整车身区域和已冻结的 200 ms 采样动作包络。两组算法都允许每个物理步重用已经完成处理的证据；尚在处理的证据不准用于控制。

| 视角/方法 | 运行数 | 创建自车 | 驾驶阶段决策 | 发出前进指令 | 进度 |
|---|---:|---:|---:|---:|---:|
| 视角 0 / 原续期 | 2 | 2 | 80 | 0 | 0 m |
| 视角 0 / 局部修复 | 2 | 2 | 80 | 0 | 0 m |
| 视角 1 / 原续期 | 2 | 0 | 0 | 0 | 0 m |
| 视角 1 / 局部修复 | 2 | 0 | 0 | 0 | 0 m |

260 帧保存 XYZ 均重新生成原始消息/拒绝结果；优化接收端与原完整接收端一致。2,636 个物理步的实际控制、证据可用时间线、车身和状态均通过重放。160 次驾驶阶段决策全部没有可用的新几何证据。原续期两次运行的驾驶阶段年龄中位数约 400 ms，修复器约 550 ms；失效后额外修复尝试增加成本，不能只报告此前成功帧上的加速。

三次视角 0 初始化在浮点比较下剩约 50 ms，但下一帧编码时间恰等于父证据到期时间，合法历史已经失效。第四次 `view0_repair_r1` 剩约 100 ms，第一帧自车观测成功续期：生成 171.589 ms、验证 34.225 ms、建模后年龄 300 ms。下一帧修复仍通过几何，但生成耗时 242.839 ms，建模后年龄 400 ms；到期时只剩不足 1 微秒的浮点表面余量，后续观测再次失去父证据。

因此不是所有失败都来自同一个启动错误；即使一次启动足够及时，续期的处理尾部仍能断链。零碰撞、零包络违例没有移动安全含义。丢包阶段没有有效驾驶消息被丢弃，也没有完成有运动的失联回退实验。

## 边界算法的独立参考核验

在看过上述结果后，冻结一个明确标记为事后分析的有限协议：所有根观测，加每次运行的首个预热/驾驶观测，共 28 帧；对全量射线及存在时的已发送子集形成 37 个比较案例。没有重新选择有利帧，也没有把同场景重复当成独立样本。

| 观测/证据 | 最长网格证书时长 | 解释 |
|---|---:|---|
| 视角 0 的 8 个根观测，全量射线 | 480.303 ms | 车辆类别的未知单元限制边界 |
| 同一批 8 个已发送射线子集 | 400.073 ms | 压缩留下的小物体类别缺口限制边界 |
| 视角 1 的 12 个根观测，全量射线 | 60.008 ms | 观测本身不足以支撑 400 ms |
| 自车出现且合法历史丢失的 7 个选定观测 | 0 ms | 自车遮挡区未被当前证据排除 |
| 第四次运行首个预热观测，合法历史存在 | 全量 480.303 / 子集 400.073 ms | 合法历史可以填补部分自遮挡缺口 |

807 次与原几何函数的对照覆盖 100–2,000 ms 的查询点、所求边界及再增加 1 微秒；全部一致。9 个非零子集边界重编码后通过未修改的完整验证器。4 项边界算法测试、5 项时钟/缓存控制测试、8 项既有集成测试通过，共 17 项不同测试。

这些结果不构成在线收益。全量边界计算本身在根观测上耗时约 882–1,209 ms，超过几何时长；全量输入有约 8.6–9.0 万条射线，超出线上 8,192 条的包上限。即便假设边界免费可得，第四次预热观测的最佳几何时长 480.303 ms，扣去已观察的 300 ms 年龄和 200 ms 动作包络仍短约 19.697 ms。不能把全量离线边界当作已实现的动作准入。

## 修正与可复现性

保留 `capture.py` 首次失败尝试和 `capture_v2.py` 八组原始运行，不修改已采集源码。首次失败是自车尚未注册到快照即读取状态；修复注册首帧和清理后，完整批次通过。失败尝试留下的自车/传感器已随本次专用旧服务器退出；重启前检查为空，完整批次最终恢复为零车辆、零传感器、异步模式。

新增 `capture_v3.py` 统一到达时间和启动预检的整数截止比较，修正三次过早启动标记及一次不足 1 微秒的可用标记。新入口只完成单元测试和保存数据审计，**没有声称又完成修正后的新驾驶批次**。原控制门已拒绝所有前进动作；这不能作为移动控制正确性的非空验证。

全部原始云、包、控制轨迹、失败尝试、协议、测试日志、源文件哈希和文件校验和一起归档。专用 CARLA 进程 49572 已独立确认退出；此前失败尝试的 53976 也已确认退出。没有创建持续研究循环。

## 对 MobiCom 2027 候选问题的影响

可以收紧的问题是：**通信和计算预算内，如何保存决定证据有效期的关键观测，而不是只压缩到满足一个预设时长？** 本轮 480.303→400.073 ms 的子集损失给出了具体机制；但还没有实现优于公平基线的时长感知选射线算法，也没有建立新颖性。

动态集合覆盖的更新与局部修复已有相关工作，见 [增量阅读记录](live_repair_reading_20261001.md)。不能把缓存、局部修复或单调二分包装成独创贡献。当前交付是可复核的有效期算法、严格时钟接口和揭示瓶颈的新实验；实际证据引导驾驶、物理契约验证、有效实时实现、真实链路与泛化评测仍未完成。
