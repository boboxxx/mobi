# Necessary deadline receiver context sensitivity

Freeze this supplement before executing it, without changing the original
capture/model/score/qualification or eight-method measurement implementation.
Do not treat shared full registration as a theoretical minimum for deadlines.

A deadline-only receiver needs the approved full source contract identity,
calibration/receipt identities, class names, four family identities, queries,
cap and motion/interpretation metadata; it does not evaluate threshold tables,
learned weights, the static background map or integer state geometry. The
catalog and model are identified by approved digests. The source is registered
and honest, exactly as in the primary deadline baseline; this does not attest
source execution or authenticate adversarial packets.

Use exactly the primary actual deadline packet bytes and full actual source
profile samples/epochs. Nothing about its source encoding or inference changes,
so this sensitivity keeps those observed fees rather than inventing/re-profiling
them. Measure three real minimal setup/decode jobs per packet. Receiver family
order is sorted SHA256(row_id+'|minimal_rx|'+family). Reconstruct all planned
360 test episodes x32 decisions, both rates and both startups; primary function
jobs remain the originally observed jobs.

The result isolates receiver context/decoder changes on that observed source
trace. It is not an independently repeated, newly simultaneous source-function
performance experiment. Any tiny difference is descriptive, not statistical
evidence of a systems advantage. Direct deadline and reusable function inference
share the same current-center event and source-relative ages; no new calibration
family or risk fit is introduced. Separate independent wire/source-job/FIFO
audit is required on both hosts before publication.
